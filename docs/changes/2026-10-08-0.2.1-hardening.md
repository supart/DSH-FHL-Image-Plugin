# 0.2.1 Hardening

Date: 2026-10-08
Branch: `dsh-fhl-image/0.2.1-development`
Target: desktop DSH `0.2.0-rc.2`

## Scope

A correctness and release-engineering pass over the `0.2.0` desktop port,
prompted by an audit of the plugin against the **shipped** desktop runtime
(`/Applications/DeepSeek Harness.app/Contents/Resources/app.asar`) rather than a
source checkout. No tool was added, removed or renamed, so `0.2.1` is a drop-in
replacement for `0.2.0`.

## Standards facts established first

Read from the asar with a small extractor, because the checkout path named in
project notes is an archive rather than a directory:

- `dsh.bundle.patch` is the only required bundle field
  (`dsh-app-boot/lib/index.js`, `bundlePatchFiles` / `bundleManifest`).
- `evaluatePluginCompatibility()` checks only `@deepseek-ai/dsh` and
  `@deepseek-ai/dsh-*` peers, with `includePrerelease: true`
  (`dsh-app-boot/lib/index.js:286`).
- `engines.dsh` is optional and unenforced; `dsh-package-manifest` documents it
  that way. It is retained as information only.
- `dsh.client` is the browser-client plugin field (`inject` + `platform`). This
  plugin is server-side only and correctly ships no client plugin.
- The packed asar contains no `.d.ts` files, so any claim resting on a shipped
  type declaration is unverifiable on this machine.

## Defects fixed

| # | Defect | Effect before the fix |
|---|---|---|
| 1 | `configureWorkers` could only `set`, never `unset` | Re-configuring with fewer keys left slots 2–10 holding revoked keys that the pool still scheduled against, while the result claimed only N workers were configured |
| 2 | Local validation shared the retryable `'request'` code | A blank prompt fanned out across the whole pool — up to 9 × 10 pointless requests per call — and surfaced as "all configured workers failed" instead of the real cause |
| 3 | `ProducedImageMemory.recall` returned the whole produced set | An implicit edit combined up to nine unrelated variations, contradicting the prompt section and four documents that promise "the newest image" |
| 4 | `decodeImage` required exact padded standard base64 | Padding-free, base64url and data-URI payloads were rejected as `invalid-image`, which then triggered defect 2's retry storm on a deterministic response quirk |
| 5 | Failed response bodies were buffered whole | Up to the 64 MiB ceiling was read before being truncated to 512 characters for the message; per task, and multiplied by `count` |
| 6 | The `task-fatal` branch rethrew the original error | A third-party fetch/undici message could carry a worker key to the model; redaction previously applied only on the aggregate path |
| 7 | `skipped` counted only excess keys | The result text said "duplicate or excess" while duplicates were never counted |
| 8 | `previewKey`'s argument was unused | Cosmetic, but it made the masking look weaker than it is; the constant `'[configured]'` is deliberate |

Fix 1 required widening the credential parameter to
`Pick<CredentialProvider, 'set' | 'unset'>`. `credentials-local` refuses to unset
a reference the launching environment supplies read-only; that refusal is
tolerated per slot so it cannot fail the keys that were successfully stored.

## Verification

- `pnpm typecheck` — `tsconfig.test.json` now covers `src` and `tests`. The
  first run exposed four real type errors that had been invisible because
  `tsconfig.json` includes only `src`: two `CredentialProvider` fixtures missing
  the five abstract record members, one `readonly Message[]` assigned to a
  mutable parameter, and one untyped `semver` import (fixed by adding
  `@types/semver`).
- `pnpm test` — 9 files / 71 tests, up from 7 files / 20.
  - `tests/worker-pool.spec.ts` (23 cases): credential-ref shape, the full
    `classifyWorkerError` table, scheduling and the concurrency cap, ordered
    results, partial failure, retry on the next worker, worker-fatal disabling,
    cooldown expiry via the injectable `now`, reset, aggregate and raw-error
    redaction, and cancellation both before start and while parked on a busy
    worker.
  - `tests/plugin-registration.spec.ts`: negative registration without an
    attachment store, plus execution of all three tool bodies against a stubbed
    `fetch` — including the assertion that a blank prompt raises the precise
    error instead of the pool-failure message, and that no request is made.
  - `tests/bundle-entry.spec.ts`: loads the built `lib/index.js` and asserts the
    plugin identity, `inject`, `apply`, Config schema and the public surface.
  - `tests/client.spec.ts`: base64 variants, invalid payloads, URL-only
    responses, the response-byte ceiling, bounded error-body reads (asserted by
    counting stream pulls), cancellation, multipart edit shape, and key
    redaction for both bearer and padded-key spellings.
- `pnpm build` / `pnpm pack` — `artifacts/fhl-plugins-dsh-fhl-image-0.2.1.tgz`,
  42 files, SHA-256
  `d90bcebc5b430c00c28ba2e8b19acd307d54896eda6ba3e0ec83a437a8d113f4`.
- The bundler began emitting a content-hashed shared chunk (`lib/client-*.js`)

- Tarball scan: no key-like text, no absolute local paths; the six README-linked
  Chinese documents are now included (previously `files` shipped only
  `docs/assets`, so those links were dead once installed).
- Compatibility gate replicated against `0.2.0-rc.2`: 7 `dsh` peers, all
  satisfied with prereleases.
- Desktop profile upgraded in place: installed copy byte-identical to the

## Deliberately not changed

- The multipart reference field naming (first reference `image`, the rest
  `image[]`) is now **pinned by a test** instead of altered. Changing it is a
  protocol change and must be verified against the live endpoint.
- `preview` remains a constant `'[configured]'`. It carries no information, but
  dropping it would be a schema change for no functional gain.
- The prompt-section name `tool:fhl-image` stays plugin-scoped. DSH's convention
  keys sections by individual tool name, but this single section documents the
  whole tool family, so renaming it after one tool would be less accurate.
- Partial-persist orphans are left to the attachment store's own reclamation.
