# 0.2.2 Reference Field Naming

Date: 2026-10-14
Branch: `main`
Target: desktop DSH `0.2.0-rc.2`

## Scope

Change one wire detail of `fhl_image_edit`: every reference image now rides the
repeated `image` multipart field, instead of `image` for the first reference and
`image[]` for the rest.

`0.2.1` recorded this exact shape as a known, deliberately deferred item — "已知但
本批次未处理：编辑请求的 multipart 字段名为首图 `image`、其余 `image[]`" — and pinned
it with a test rather than changing it, because altering it is a protocol change
that needs a live endpoint check. This release is that change, ported from the
Codex plugin's `0.2.2`. No tool was added, removed or renamed; the tool surface,
the host half, the credential references, `cordis.patch.yml` and the browser half
are untouched, so `0.2.2` is a drop-in replacement for `0.2.1`.

## Why the mixed shape was wrong

The Codex plugin's `v0.2.2` release note states the finding:

> 根因不是上游只收到一张图，而是默认上传格式混用了两种字段：
> `image` = 图1、`image[]` = 图2。FHL 没有把两种字段稳定合并为同一个参考图数组，
> 导致图2的人物身份参考失效。

Both images did reach the request, but the second one's identity contribution
never reached the model: face, glasses, hairstyle and clothing from reference 2
were dropped in multi-reference composites. The Codex plugin changed its
production form builder from `mixed` to `repeat-image` and confirmed on the live
endpoint that both originals upload and reference 2's identity survives.

## What changed

- `src/client.ts`: the position-dependent `formSourceField(index)` helper is
  replaced by one `EDIT_SOURCE_FIELD = 'image'` constant used for every part. The
  `mixed` and `array` shapes the Codex plugin keeps for its `--field-mode`
  diagnostics are not ported — this plugin has no diagnostic mode to carry them.
- `tests/client.spec.ts`: the pin is inverted. The two-reference case asserts two
  `image` parts and no `image[]` key, and a new case drives a full
  `MAX_EDIT_SOURCES` (10) edit and asserts one `image` part per reference with no
  `image[]` key at all, so the field name can never again depend on position.

## Verification status

Not re-verified against the live FHL endpoint from this plugin. The Codex plugin
verified the equivalent request shape on its own real link; this port is covered
by unit tests only. A live check needs a configured worker and a billable request.
